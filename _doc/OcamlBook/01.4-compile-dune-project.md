# 1.4 編譯與 dune 專案結構

小腳本可用 `ocaml` 直接跑，正式專案一律用 `dune`。

## 1. 為什麼用 dune

- 宣告式建置：一個 `dune` 檔取代手寫 `ocamlopt` 指令。
- 自動依賴分析、增量編譯、跨平台。
- 原生支援 executable、library、test、生成規則。

## 2. 最小專案

```bash
dune init proj hello
cd hello
tree
```

結構：

```text
hello/
├── dune-project
├── lib/
│   ├── dune
│   └── hello.ml
├── bin/
│   ├── dune
│   └── main.ml
└── test/
    ├── dune
    └── test_hello.ml
```

`bin/dune`：

```lisp
(executable
 (public_name hello)
 (libraries hello))
```

`bin/main.ml`：

```ocaml
let () = print_endline Hello.(greet "Ada")
```

執行：

```bash
dune exec hello
dune build
dune clean
```

## 3. 編譯模式

| 指令 | 產物 | 用途 |
| --- | --- | --- |
| `dune exec <name>` | 建置+執行 | 開發期 |
| `dune build` | `_build/` | CI 檢查 |
| `dune runtest` | 執行測試 | 測試 |
| `dune fmt` / `ocamlformat` | 格式化 | 風格統一 |

`dune-project` 指定語言版本與依賴：

```lisp
(lang dune 3.16)
(name hello)
(package (name hello) (depends ocaml dune))
```

## 4. 常用工作流

```bash
dune init lib mylib
dune build @fmt --auto-promote   # 自動格式化
dune utop lib                    # 在函式庫上下文開 REPL
dune ocaml top                   # 底層頂層
```

除錯旗標：

```bash
dune exec --profile release ./bin/main.exe
OCAMLRUNPARAM=b dune exec ./bin/main.exe   # 顯示 backtrace
```

## 練習

1. 用 `dune init proj demo` 建專案，改 `main.ml` 印出 `Sys.ocaml_version`。
2. 在 `lib/dune` 加 `(libraries str unix)` 並使用 `Str` 模組，觀察 dune 如何處理依賴。
3. 執行 `dune fmt` 前後 diff，熟悉 `ocamlformat` 預設風格。

## 常見錯誤

- `Error: Library "xxx" not found`：需在 `dune` 的 `(libraries ...)` 宣告並 `opam install`。
- 檔名與模組名：`my_lib.ml` 對應模組 `My_lib`，大小寫需對應。
