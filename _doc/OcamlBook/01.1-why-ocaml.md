# 1.1 為什麼學 OCaml

OCaml 是工業級函數式語言，兼顧表達力與安全。本節說明它的定位、強項與適用場景。

## 1. OCaml 是什麼

- 1973 年 ML → 1996 年 Objective Caml → 今日 OCaml 5.5。
- 靜態型別 + 全域型別推論：多數時候不用寫型別註解，編譯器仍能抓錯。
- 預設不可變（immutable），需要可變才顯式使用 `ref`、`mutable`。
- 同時支援函數式、命令式、模組化與物件導向四種典範。
- 原生編譯（`ocamlopt`）速度接近 C，位元組碼（`ocamlc`）可攜。

## 2. 強項一覽

| 特性 | 說明 | 對比 |
| --- | --- | --- |
| 代數資料型別 + 模式匹配 | `type` + `match` 表達 AST、協定、狀態機極簡潔 | 比 Go `switch`、Python `if/elif` 更安全（窮盡檢查） |
| 模組系統 + Functor | 大型專案的命名空間與泛型機制 | 比 C++ template 錯誤訊息友善，比 Java 泛型強大 |
| 效能 | native code、增量 GC，5.x 多核並行 | Web、編譯器、靜態分析、金融系統愛用 |
| 併發 | `Domain` 真並行 + `Effect` 代數效應 + `Eio` | Python GIL、Node 單執行緒之外的另一條路 |
| 工具鏈 | `opam` + `dune` + `utop` + `ocaml-lsp` | 媲美 cargo / npm 的現代體驗 |

知名用戶：Jane Street（金融交易）、Meta（Hack、Flow、Infer）、Docker（早期）、Coq 證明助手即以 OCaml 寫成。

## 3. 什麼時候選 OCaml

適合：

- 編譯器、直譯器、靜態分析、符號運算。
- 需要正確性（型別即規格）又要速度的後端服務。
- 想學透函數式、型別系統、模組設計。

不適合：

- 要大量現成 Web 框架、手機 SDK 生態（不如 TypeScript / Kotlin）。
- 團隊完全無函數式背景又要求一週上線（學習曲線存在）。

## 4. OCaml 5.x 的關鍵變化

- 5.0：多核 runtime，引入 `Domain`、`Effect`。
- 5.3：深層 effect handler 語法、MSVC 支援、UTF-8 原始碼。
- 5.4：不可變陣列 `iarray` 语法、`Pair`、`Pqueue`、`Repr` 模組。
- 5.5（本書基準）：模組相依函式、重定位編譯器、60+ 新 Stdlib 函式、GC 改進。

> 4.14 是長期支援版；新專案直接用 5.5。

## 常見誤解

- 「函數式 = 不能有副作用」：錯。OCaml 允許 `ref`、`while`、`for`，只是鼓勵預設不可變。
- 「型別推論 = 動態型別」：錯。推論仍是靜態檢查，執行前就擋下錯誤。
