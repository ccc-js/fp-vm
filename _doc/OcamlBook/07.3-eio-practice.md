# 7.3 Eio 實務併發

`Eio` 是 OCaml 5 官方推薦的併發函式庫：結構化併發 + 能力（capability）安全。實務併發優先用它，而非手寫 `Domain` + `Effect`。

## 1. 安裝與最小程式

```bash
opam install eio -y
```

`bin/dune`：

```lisp
(executable
 (public_name fetch_demo)
 (libraries eio_main))
```

```ocaml
open Eio.Std

let () =
  Eio_main.run @@ fun env ->
  let clock = Eio.Stdenv.clock env in
  Fiber.both
    (fun () ->
      Eio.Time.sleep clock 0.5;
      print_endline "task A done")
    (fun () ->
      Eio.Time.sleep clock 0.3;
      print_endline "task B done")
```

`Eio_main.run` 建立事件迴圈，`Fiber.both` 並行跑兩個纖程（fiber），皆結束才返回：結構化併發。

## 2. 網路與檔案

```ocaml
let fetch env ~net ~clock host path =
  let conn = Eio.Net.connect ~sw:env#sw net (`Tcp (host, 80)) in
  (* 實務用 cohttp-eio / piaf 等高階函式庫，此處示意 *)
  ignore (conn, clock, path)

let read_file env path =
  let fs = Eio.Stdenv.fs env in
  Eio.Path.load Eio.Path.(fs / path)
```

能力式設計：`env` 攜帶 `clock`、`net`、`fs`，函式只拿所需能力，易測試、易稽核。

## 3. Switch 與取消

```ocaml
open Eio.Std

let () =
  Eio_main.run @@ fun env ->
  Switch.run @@ fun sw ->
    Fiber.fork ~sw (fun () -> print_endline "background");
    print_endline "main";
    (* 離開 Switch 時等待所有 fork 的 fiber *)
```

取消、超時皆經 `Switch` / `Time.with_timeout` 結構化處理，不會洩漏背景任務（對比裸 `Thread.create`）。

## 4. 何時用什麼

| 需求 | 工具 |
| --- | --- |
| CPU 密集平行 | `Domain`（7.1） |
| 高併發 IO（http、ws、db） | `Eio` + `cohttp-eio` |
| 自訂控制流（排程、non-det） | `Effect`（7.2） |
| 舊 Thread 程式 | `Thread` 仍可用，但新碼用 `Eio` |

## 練習

1. 用 `Fiber.both` 並行 sleep 兩個不同時間，觀察結束順序。
2. 用 `Switch.run` + `Fiber.fork` 啟動 10 個任務並等待。
3. 將一個阻塞 IO 改為 `Eio` 版，比較程式碼結構。

## 常見錯誤

- 在 `Eio` fiber 內呼叫阻塞 syscall 而未用 `Eio` 包裝（卡住整個排程）。
- 把 `env` 存成全域：違反能力 discipline，應顯式傳遞。
