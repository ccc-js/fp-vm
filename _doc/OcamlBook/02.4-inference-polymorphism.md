# 2.4 型別推論與多型

OCaml 的 Hindley–Milner 推論讓你少寫註解，仍享靜態檢查。

## 1. 推論實例

```ocaml
let id x = x
(* val id : 'a -> 'a *)

let fst (a, b) = a
(* val fst : 'a * 'b -> 'a *)

let len l = List.length l
(* val len : 'a list -> int *)
```

`'a` 是型別變數：`id` 對任何型別成立，稱為參數多型。

在 `utop` 用 `#show` 驗證：

```ocaml
#show id;;
(* val id : 'a -> 'a *)
```

## 2. 何時加註解

推論雖強，公開 API 仍建議註解（文件 + 提早報錯）：

```ocaml
let square : int -> int = fun x -> x * x
let add (a : int) (b : int) : int = a + b
let circle_area (r : float) : float = 3.14159 *. r *. r
```

區域註解：

```ocaml
let f (x : int list) = List.length x
let y = (42 : int)
```

## 3. value restriction（值限制）

只有「語法上的值」才能泛化。多型 `ref` 會被限制，避免可變Cell 破壞型別安全：

```ocaml
let r = ref None
(* val r : '_weak1 option ref — 未泛化 *)

let f () = ref None
(* val f : unit -> 'a option ref — 每次呼叫 fresh，可泛化 *)
```

實務規則：頂層 `let x = <有計算>` 若含函式呼叫，型別可能變 `_weak`，加註解或改為函式即可。

```ocaml
let empty1 = []        (* 'a list，OK：[] 是值 *)
let empty2 = List.map Fun.id []  (* '_weak list，需註解 *)
let empty2 : 'a list = List.map Fun.id []
```

## 4. 單態 vs 多態的錯誤訊息

```ocaml
let r = ref 0 in
r := "hi"
(* Error: This expression has type string but ... int *)
```

一旦 `ref 0` 定為 `int ref`，就不能再存字串。這正是靜態安全的價值。

## 練習

1. 在 `utop` 輸入 `let pair a b = (a, b)`，讀出推論型別。
2. 寫 `let apply f x = f x`，推測型別後用 `#show` 驗證。
3. 故意寫 `let f x = x + 1.0`，解讀錯誤訊息。

## 常見錯誤

- 期望 `id` 同時是 `int->int` 與 `string->string` 發生衝突：通常是 value restriction，需 eta 展開為 `fun x -> ...`。
- 過度註解導致多型喪失：`let id : int -> int = ...` 就不再是 `'a -> 'a`。
