# 5.4 dune 函式庫管理與測試

從單檔進化到可維護專案：切函式庫、加測試、管依賴。

## 1. 切出函式庫

```text
lib/dune:
(library
 (name hello)
 (libraries str unix))
```

```ocaml
(* lib/hello.ml *)
let greet name = "Hello, " ^ name ^ "!"

(* lib/hello.mli *)
val greet : string -> string
```

`bin/main.ml` 引用：

```ocaml
let () = print_endline (Hello.greet "Ada")
```

```lisp
; bin/dune
(executable
 (public_name hello)
 (libraries hello))
```

## 2. 加測試（alcotest / expect）

```bash
opam install alcotest -y
```

```lisp
; test/dune
(test
 (name test_hello)
 (libraries hello alcotest))
```

```ocaml
(* test/test_hello.ml *)
let test_greet () =
  Alcotest.(check string) "greet" "Hello, Ada!" (Hello.greet "Ada")

let () =
  Alcotest.run "hello" [("greet", [Alcotest.test_case "basic" `Quick test_greet])]
```

```bash
dune runtest
dune runtest --force
```

Dune 內建 `cram`（`.t` 檔）適合 CLI 輸出測試：

```text
; test/cli.t
  $ hello Ada
  Hello, Ada!
```

## 3. 依賴管理

`dune-project`：

```lisp
(lang dune 3.16)
(name hello)
(generate_opam_files true)
(package
 (name hello)
 (depends ocaml dune (alcotest :with-test)))
```

```bash
opam install . --deps-only --with-test -y
dune build
dune runtest
```

## 4. 格式化與文件

```bash
echo '(lang ocaml)' > .ocamlformat
dune fmt --auto-promote
dune build @doc
```

CI 最小集合：`dune build` + `dune runtest` + `dune fmt --check`。

## 練習

2. 為 CLI 加一個 `cli.t` cram 測試。
3. 執行 `dune build @doc` 並瀏覽產生的 HTML。

## 常見錯誤

- `test` 的 `(libraries ...)` 漏加被測函式庫。
- `generate_opam_files true` 後忘記 `dune build` 更新 `.opam`。
